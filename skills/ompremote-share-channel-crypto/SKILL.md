# 共享盘作业通道：加密与密钥卫生

适用于"控制端往 SMB 共享投作业文件 → 机台执行 → 结果写回共享"这类通道。

## 1. 你要保护的到底是什么

- **机密性**：共享盘通常可被同事/IT 读到，作业脚本与结果不能明文躺着；
- **完整性**：谁都能写共享，就必须做到"写了也执行不了"；
- **可归因**：出问题时能回答"谁在什么时候对哪台机做了什么"。

三条里最容易漏的是第三条：只加密不改日志，事故时无法定位；只记录不加密，内容全裸。

## 2. 最小可信设计

| 项 | 做法 |
|---|---|
| 作业体 | AES-256-CBC（或 GCM）+ 独立 HMAC |
| 签名 | HMAC-SHA256 覆盖规范串：`id\|kind\|machine\|ts\|nonce\|sha256(密文)\|超时` |
| 防重放 | 随机 nonce + 时间窗（±15 min）+ 机台绑定 |
| 结果 | 同样加密；MAC 不符一律拒收，不做"尽力解析" |
| 密钥 | 控制端持 master；机台只持有自己的 seed（HKDF 派生） |
| 落盘 | 机台侧用 DPAPI 封装，拷走 `settings.ini` 无效 |

## 3. 三条必须写进代码的规则

1. **没有密钥就不要假装有**：无钥时机台应回退到"可被修复"的状态并大声记录，而不是静默拒绝一切
   （否则一次密钥下发失误就把机器变成砖）。
2. **不要静默降级**：MAC/时间窗/nonce 任一不符，拒收并在结果里写明原因。
3. **作业 payload 用完即删**：共享盘上残留的脚本（尤其密钥下发脚本）等于把密钥贴在公告栏。

## 4. 轮换

双钥窗口（新钥下发 → 心跳上报代数 → 复验 → 销毁旧钥），不要追求"同一时刻全部切换"，那必然掉线。

## 5. 运营边界（重要）

- 内容加密，**路径/时间/主机名/审计保持可读**。把心跳和作业清单也加密，等于让排障和审计都做不了，
  外部看起来就是"不可解释的通道"；
- 不做跳板/中继（用别人的机器转发流量是未授权控制他人计算机，性质会从内部违规变成刑事）；
- 不做进程注入、不装驱动、不改终端安全配置；
- 如果安全软件拦截了你的加载器：**向 IT 申请例外或改设计**，不要对抗检测。

## 6. 别指望"本机加白"

企业版终端安全的配置通常在受保护目录的数据库里、由控制台下策略下发，本机账号没有写权限。
正确路径是让 IT 在控制台下发目录/进程例外，而不是脚本去改安全软件。
